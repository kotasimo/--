# 院試メモアプリ 開発方針

このアプリは、名古屋大学工学部系の院試対策を「問題ごと」に整理するための個人用Webアプリです。

目的は、ただ過去問画像を置くことではなく、問題を解いたときの疑問、ChatGPT/Codexとの相談、参考書から追加した問題、あとで見返したいメモを、科目・年度・問題単位で迷子にしないことです。

## 基本方針

- 表は一覧・整理用にする。
- 詳細な内容は、各年度または各追加問題の詳細ページに集約する。
- 過去問と追加問題は、できるだけ同じ画面構成にする。
- PCでは一覧表を使って全体を見渡し、スマホでは詳細ページを中心に使う。
- 問題画像と解答画像は、余計な枠や説明を減らして大きく表示する。
- メモは短くても長くても残せる日記的な場所にする。
- チャットログは、その問題について何を質問したかを後から追える場所にする。
- 数式表示は完璧さよりも、内容を保存してあとで参照できることを優先する。

## データの考え方

コード、画像、メモ、相談ログは役割を分ける。

- GitHub: アプリのコード、固定の過去問画像、固定の手書き解答画像を保存する。
- Supabase: 表の記録、問題メモ、追加問題、追加画像、相談ログを保存する。
- Vercel: スマホや別PCからアクセスできる公開先として使う。
- Codexのチャット: 開発作業や問題相談の作業場として使う。

Codexのこのチャット自体は、基本的にこのPCの作業用チャットです。別PCやスマホにそのまま同期するものではありません。

ただし、Codexで相談した内容をアプリ内の相談ログに保存しておけば、Supabase経由でスマホや別PCから見返せます。

## 画面構成

### ホーム

ホームは、科目ごとの一覧表を表示する場所です。

表はあくまで整理用です。各行から問題、解答、チャット、メモを軽く確認できるようにし、詳しい確認や編集は詳細ページで行います。

表では、開くボタンが並びすぎて見た目が重くならないように、状態が分かる表示や簡潔な操作を優先します。

### 過去問詳細

過去問詳細は、年度ごとに次の情報を見る場所です。

- 問題画像
- 手書き解答画像
- 相談ログ
- メモ

問題画像と解答画像は、画像そのものを大きく見られることを優先します。スマホでは特に、上部の余計な表示を減らして画像に画面を使います。

### 追加問題

追加問題は、参考書や演習書などから追加した問題を管理する場所です。

過去問と同じように、表示画面では次を切り替えます。

- 問題
- 解答
- チャット
- メモ

編集画面では、基本的に次だけを扱います。

- タイトル
- 教科
- 問題画像
- 解答画像

記録やメモは編集画面では扱わず、表示画面側のメモや表側で扱います。

新規追加した問題は、保存ボタンを押したタイミングでSupabaseに保存します。保存前にリロードすると消えるため、画像やタイトルを入れたら保存する必要があります。

### チャット

チャットは、その問題について質問した内容を保存する場所です。

目次には自分の質問だけを並べます。クリックすると、その質問の位置に飛べるようにします。

チャット本文は、できるだけChatGPT/Codexの表示に近い読み心地にします。ただし数式については、必要に応じてLaTeXのまま保存してもよいです。大事なのは、後から「何を聞いたか」「何で詰まったか」「どう考えたか」を参照できることです。

## チャット保存の方針

このアプリでいう「チャット」は、サイト内にある各問題専用の相談ログです。

Codexのこの作業チャットそのものを同期するのではなく、問題について相談した内容を、必要な単位でサイト側の相談ログに保存します。保存先はSupabaseです。Supabaseに保存された相談ログは、PCでもスマホでも同じサイトURLから見返せます。

### 保存する目的

チャット保存の目的は、きれいな解答集を作ることではありません。

目的は、次のような情報を問題ごとに残すことです。

- どの問題で何を質問したか。
- どこで詰まったか。
- どの考え方で解けばよいか。
- 自分が間違えやすいポイントは何か。
- あとで復習するとき、何を見ればよいか。

そのため、文章や数式の見た目が多少粗くても、内容が失われないことを優先します。

### 保存先の単位

相談ログは、必ず問題単位で保存します。

過去問の場合は、次の単位で保存します。

```text
科目 + 年度
例: 材力 2024年度
```

追加問題の場合は、次の単位で保存します。

```text
追加問題ID
表示上は タイトル + 教科
例: 材料力学 参考書の曲げ応力問題
```

科目全体の相談や勉強方針の相談は、特定の問題に無理に入れません。必要になったら、将来的に「全体相談ログ」または「科目メモ」を作ります。

### 保存する内容

基本的には、ユーザーの質問とCodexの回答をセットで保存します。

保存する内容:

- ユーザーの質問文
- Codexの回答
- 必要なら補足メモ
- 必要ならLaTeX形式の数式

保存しなくてよい内容:

- UI修正や開発作業だけの会話
- GitHub、Vercel、Supabaseの操作相談
- 問題と関係ない雑談
- 一時的な確認だけの短いやり取り

ただし、ユーザーが「これも保存して」と言った場合は保存します。

### 保存のタイミング

問題相談を始めるときは、最初に対象を宣言します。

```text
今から 2024 材力 の質問
```

追加問題の場合:

```text
今から 追加問題「材料力学の参考書 曲げ応力」の質問
```

この宣言以降の問題相談は、その対象の相談ログへ自動保存する前提で扱います。

ユーザーが毎回「保存して」と言う必要はありません。対象問題が決まっている間は、問題に関する質問とCodexの回答を1セットとして、その都度相談ログに保存します。

相談が終わったら、区切りを宣言します。

```text
一旦この問題の質問終わり
```

この区切り以降は、その問題への自動保存を止めます。

途中でユーザーが次のように言った場合は、直前までの内容をまとめ直して保存してもよいです。

```text
ここまで保存して
この回答をチャットに入れて
この内容をこの問題の相談ログに残して
```

対象が曖昧な場合は、自動保存せずに確認します。

例:

```text
これは2024材力に保存する？ それとも追加問題側？
```

### 表示の方針

相談ログ画面では、自分の質問が目次になります。

目次には、ユーザーの質問だけを1行で表示します。長い質問は1行に省略し、ホバーで全文を確認できるようにします。

チャット本文では、ユーザーの質問とCodexの回答を時系列で表示します。

古い相談を上、新しい相談を下に表示します。通常のチャットと同じように、会話が下へ下へ積み上がっていく形にします。

日付や時刻は基本的に表示しません。あとで見返すときに大事なのは、いつ話したかより、何を聞いて何を理解したかだからです。

### メモとの違い

チャットは、やり取りそのものを残す場所です。

メモは、あとで見返すために短く整理した内容を残す場所です。

例:

チャット:

```text
Q. なぜB点の反力を下向きに取るの？
A. 図の向きに合わせて未知量を置いているだけ。計算結果が負なら逆向きという意味になる...
```

メモ:

```text
反力の向きは仮定でよい。符号で実際の向きが決まる。
```

相談ログに全部残し、重要な復習ポイントだけメモに整理するのが理想です。

### Codexが保存するときの注意

Codexが相談ログに保存するときは、次を守ります。

- 対象の科目・年度・追加問題を確認してから保存する。
- ユーザーの質問文はできるだけそのまま残す。
- 回答は意味が変わらないように残す。
- 数式は崩れる場合、LaTeX形式のまま保存してよい。
- 問題文や解答画像と重複する内容を無理に増やさない。
- 相談ログとメモを混ぜない。
- どこに保存したかを作業後に伝える。

### 保存できない・注意が必要な場合

Supabaseの環境変数が入っていない環境では、保存がローカル保存になり、別PCやスマホに同期されません。

Vercelで使う場合は、Vercel側にも次の環境変数が必要です。

```env
VITE_SUPABASE_URL=SupabaseのProject URL
VITE_SUPABASE_PUBLISHABLE_KEY=SupabaseのPublishable key
```

スマホで追加した問題や画像がPCで見えない場合は、まずSupabase保存になっているかを確認します。

## Codexとの運用

問題について質問するときは、最初に対象を指定します。

例:

```text
今から 2024 材力 の質問
```

追加問題の場合:

```text
今から 追加問題「材料力学の参考書 曲げ応力」の質問
```

その後に普通に質問します。

例:

```text
(1)の問題を解いて
ここでなぜ反力がこうなるの？
この考え方をメモにまとめて
```

相談が終わったら、区切りを明確にします。

```text
一旦この問題の質問終わり
```

Codex側では、必要に応じてそのやり取りを該当問題の相談ログやメモに保存します。

## 別PCで使うとき

別PCでは、GitHubからリポジトリをcloneして同じ環境を作ります。

```powershell
git clone GitHubのURL
cd 院試
npm install
```

そのPCにも `.env.local` を作ります。

```env
VITE_SUPABASE_URL=SupabaseのProject URL
VITE_SUPABASE_PUBLISHABLE_KEY=SupabaseのPublishable key
```

その後、次で起動します。

```powershell
npm run dev
```

コードはGitHubで同期し、データはSupabaseで同期します。

## 次やること

### 優先度 高

- 追加問題の保存動作を実機で確認する。
- Vercel側にSupabase環境変数が入っているか確認する。
- スマホで追加した画像がPCでも表示されるか確認する。
- 過去問と追加問題の画像表示をさらにそろえる。
- 相談ログを問題ごとに保存する運用を固める。

### 優先度 中

- ホーム表の見た目をさらに整理する。
- 表の「記録」「メモ」「チャット」の表示方法を見直す。
- 追加問題一覧で、タイトルと教科が分かりやすく見えるようにする。
- スマホ表示で、詳細ページの上部余白をさらに減らす。
- チャットの質問目次を増えたときでも使いやすくする。

### 優先度 低

- 数式表示を必要に応じて改善する。
- 画像の並び替えをできるようにする。
- 画像削除・差し替えの操作性を整える。
- READMEをもう少し一般向けに整理する。
- 古い `outputs` や `work` の成果物を残すものと消すものに分ける。

## 判断に迷ったときの基準

- 表は軽く、詳細は深く。
- スマホでは一覧より詳細を優先。
- 画像はできるだけ大きく。
- 保存先はSupabaseに寄せる。
- 追加問題は過去問と同じ構成に寄せる。
- UIは機能説明を増やすより、ボタン名と配置で分かるようにする。
- 完璧な数式表示より、相談内容が失われないことを優先する。
